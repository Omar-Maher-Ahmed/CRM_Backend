# 🚀 نظرة عامة على مشروع CRM Backend

## 🛠️ دليل البدء والتشغيل لأعضاء الفريق (Setup Guide)

لتشغيل المشروع على جهازك المحلي (Localhost) كعضو في الفريق، يرجى اتباع الخطوات التالية بالترتيب:

### 1️⃣ تحميل الاعتمادات (Install Dependencies)
قم بفتح الـ Terminal في مجلد المشروع وقم بتشغيل الأمر التالي لتحميل كل الحزم (Packages) اللازمة:
```bash
npm install
```

### 2️⃣ إعداد متغيرات البيئة (Environment Variables)
يجب التأكد من وجود ملف `.env` في المسار الرئيسي للمشروع، ويجب أن يحتوي على الأقل على القيم التالية:
```env
DB_PORT=5432
DB_HOST=localhost
DB_USERNAME="postgres"
DB_PASSWORD=123456  # (أو الباسورد الخاص بالداتابيز عندك)
DB_DATABASE="crm"
PORT=5000
JWT_ACCESS_SECRET=helloWorld
```

### 3️⃣ تشغيل قاعدة البيانات (Database Setup)
المشروع جاهز بملف `docker-compose.yml` لإنشاء قاعدة بيانات PostgreSQL بسهولة، قم بتشغيل هذا الأمر:
```bash
docker-compose up -d
```
*(تأكد من أن تطبيق Docker Desktop يعمل على جهازك).*

### 4️⃣ تشغيل السيرفر (Run the Server)
الآن يمكنك تشغيل المشروع في وضع التطوير (Development Mode) باستخدام الأمر:
```bash
npm run start:dev
```
عند نجاح التشغيل، سترى رسالة: `🚀 Application is running on: http://localhost:5000`

### 5️⃣ الروابط الهامة بعد التشغيل
- **مسار الدخول (REST API):** `http://localhost:5000/auth/login`
- **واجهة GraphQL:** `http://localhost:5000/graphql` (يمكنك استخدامها لاختبار الـ Queries والـ Mutations).

## 💡 1. ما هي فكرة المشروع؟
المشروع عبارة عن **نظام إدارة علاقات العملاء (CRM)** من جهة الخادم (Backend).
تم بناء النظام باستخدام تقنيات حديثة وقوية لضمان الأداء العالي والقابلية للتوسع، وتشمل:
- **NestJS** 🛡️ (إطار عمل قوي ومنظم)
- **GraphQL** 🔗 (للاستعلامات المرنة والسريعة)
- **TypeORM** 🗄️ (للتعامل مع قواعد البيانات)
- **PostgreSQL** 🐘 (كقاعدة بيانات علائقية متينة)

**الهدف الأساسي:** بناء نظام مركزي لإدارة بيانات الموظفين والعملاء وتتبع التفاعلات بينهم بكفاءة وسرعة.

---

## 🎯 2. ما هي المشاكل التي يحلها؟
يستهدف النظام القضاء على العشوائية وتشتت البيانات، ويقدم الحلول التالية:

- 📂 **مركزية البيانات:** حفظ بيانات العملاء في مكان واحد بدلاً من الاعتماد على ملفات الـ Excel المشتتة.
- 👥 **تنظيم الهيكل الإداري:** تنظيم صلاحيات الموظفين وتوضيح التسلسل الهرمي (من هو المدير ومن الموظف المسؤول) من خلال ميزات مثل `managerId` و `salary`.
- 🤝 **تحسين جودة خدمة العملاء:** سهولة الوصول لتاريخ التعاملات مع العملاء، مما يسرع الدعم ويزيد فرص المبيعات.
- ⚡ **واجهة برمجية (API) قوية:** بفضل GraphQL، يمكن لأي واجهة أمامية (Frontend) أو تطبيق هاتف ذكي (Mobile App) الاتصال بالنظام بسلاسة فائقة.

## 💼 3. أين يمكن بيع هذا النظام؟
النظام مرن للغاية ويمكن تسويقه بعدة طرق:

| السوق المستهدف | طريقة البيع / الاستفادة |
| :--- | :--- |
| **نظام كخدمة (SaaS)** ☁️ | استضافة النظام وبيعه باشتراك شهري للشركات الصغيرة والمتوسطة. |
| **شركات محددة (B2B)** 🏢 | بيعه كحل مخصص لشركات العقارات، وكالات التسويق، مراكز الاتصال (Call Centers)، وشركات التأمين. |
| **العمل الحر (Freelance)** 💻 | بيعه كـ Boilerplate (كود أساسي جاهز) للمبرمجين أو الشركات لتسريع وقت التطوير. |

## 👥 4. من هم المستخدمون المحتملون؟
- 📈 **فرق المبيعات:** لتسجيل العملاء المحتملين (Leads) ومتابعة الصفقات.
- 🎧 **ممثلو خدمة العملاء (Support):** لمراجعة سجل العميل وتقديم الدعم المناسب.
- 👨‍💼 **المديرون:** لمتابعة أداء الموظفين وإدارة الهيكل التنظيمي (عن طريق `managerId`).
- 📊 **إدارة الموارد البشرية (HR):** لإدارة الموظفين والرواتب (`salary`) وحالة النشاط (`isActive`).
- 👑 **أصحاب الأعمال:** للحصول على رؤية شاملة وتقارير عن أداء الشركة والعملاء.

## 🏗️ 5. ماذا تم إنجازه في المشروع حتى الآن؟
من خلال فحص الكود الحالي، تم بناء أساس قوي يتضمن:

1. ⚙️ **تأسيس المشروع (Setup):** بناء الهيكل باستخدام NestJS وربطه بقاعدة بيانات PostgreSQL عبر TypeORM.
2. 🔌 **إعداد GraphQL:** تجهيز Apollo Server لاستقبال الـ Queries والـ Mutations.
3. 👤 **نظام المستخدمين (User Module):**
   - جدول المستخدمين `Users` بخصائصه (الاسم، الإيميل، الباسورد، الراتب، رقم الهاتف، المدير).
   - **الاستعلامات (Queries):** جلب كافة المستخدمين `getAllUsers`، ومستخدم محدد `getUser`.
   - **التعديلات (Mutations):** إضافة `createUser`، تعديل `updateUser`، حذف `deleteUser`، وتغيير كلمة المرور `updatePassword`.
   - **الحماية:** تشفير كلمات المرور باستخدام `bcrypt`.
4. 🔐 **نظام المصادقة (Auth Module):** بدء التأسيس باستخدام `Passport` و `JWT`.
5. 🤝 **نظام العملاء (Customer Module):** تم إنشاء المجلد الأساسي `src/customer` ومستعد للبرمجة.

## 🗂️ 6. ما هو شكل البيانات المدخلة في قاعدة البيانات؟

### 🧑‍💻 بيانات المستخدمين (الموظفين) الحالية:
مجهزة بالفعل في النظام وتتكون من:
```graphql
type User {
  id: ID!               # المعرف الفريد
  fullName: String!     # الاسم بالكامل
  email: String!        # البريد الإلكتروني
  phone: String!        # رقم الهاتف
  salary: Float!        # راتب الموظف
  isActive: Boolean!    # هل الحساب نشط؟
  managerId: ID         # معرف المدير (إن وجد)
  createdAt: DateTime!  # تاريخ الإنشاء
  updatedAt: DateTime!  # تاريخ التعديل
}
```

### 🤝 بيانات العملاء (Customers) المتوقعة:
بناءً على فكرة المشروع، عند برمجة نظام العملاء، ستكون البيانات التقريبية كالتالي:
- 🔑 `id`: المعرف الفريد للعميل.
- 👤 `name`: اسم العميل.
- 📧 `email` و 📱 `phone`: بيانات التواصل مع العميل.
- 🏢 `company`: اسم الشركة التابع لها العميل (إن وجد).
- 🚦 `status`: حالة العميل (عميل محتمل، مؤكد، تم الرفض، إلخ).
- 📌 `assignedTo`: معرف الموظف المسؤول عن العميل.
- 📝 `notes`: أي ملاحظات إضافية بخصوص العميل.

## 📱 7. (Mobile / Frontend Integration)

### 🔐 1. كيف يتم تسجيل الدخول والمصادقة (Authentication Flow)؟
- **الإجابة من المشروع:** 
  - يوجد مسار (REST API) جاهز لتسجيل الدخول: `POST /auth/login`.
  - يجب إرسال `email` و `password` بصيغة JSON.
  - تعتمد المصادقة على **JWT (JSON Web Token)** وترجع الـ Token في حالة نجاح العملية.
  - **حماية إضافية:** تم تفعيل Rate Limiter لمنع التخمين العشوائي للباسورد (حد أقصى 5 محاولات في الدقيقة)، وتم عمل Regular Expressions (Regex) لمنع حقن الأكواد الخبيثة في الإيميل أو الباسورد (XSS/SQL Injection).
### 🌐 2. ما هي تفاصيل الاتصال (Endpoint Details)؟
- **الإجابة من المشروع:** 
  - السيرفر يعمل حالياً على البورت `5001`.
  - مسار الـ GraphQL الأساسي هو: `http://localhost:5001/graphql`.
  - يوجد ملف `schema.gql` جاهز يمكن استخدامه لتوليد الأكواد (Code Generation).

### 📄 3. كيف تعمل تقسيم الصفحات والفلترة (Pagination & Filtering)؟
- **الإجابة من المشروع:** حالياً استعلام `getAllUsers` يقوم بإرجاع كل المستخدمين كقائمة واحدة `[User!]!` بدون تقسيم.
- **سيتم تحديد الآتي:** آلية الفلترة وتطبيق الـ Pagination (مثل Limit و Offset) في المستقبل لتسهيل عرض البيانات.

### 🖼️ 4. كيف نتعامل مع الصور والملفات (File Uploads)؟
- **الإجابة من المشروع:** غير متوفر حالياً في الكود.
- **سيتم تحديد الآتي:** الطريقة المعتمدة لرفع الصور (هل سنستخدم تخزين سحابي مثل Amazon S3 أم رفع محلي، وهل ستكون عبر REST أم GraphQL).

### ⚡ 5. هل يوجد تحديثات فورية (Real-time / WebSockets)؟
- **الإجابة من المشروع:** غير متوفر حالياً في الـ Schema (لا يوجد `Subscriptions`).
- **سيتم تحديد الآتي:** مدى الحاجة لدعم الـ Real-time عبر WebSockets عند إضافة عملاء جدد لتحديث واجهة الموبايل فوراً.

### 🚨 6. كيف أتعامل مع الأخطاء (Error Handling)؟
- **الإجابة من المشروع:** يتبع النظام أسلوب GraphQL القياسي، حيث ترجع الأخطاء في مصفوفة `errors` بداخل الاستجابة توضح نوع الخطأ لتسهيل التعامل معه في الواجهة.
